# 鬼畜节奏规律拆解：以《改革春风吹满地》为样本

样本：B 站 av19390801（BV1bW411n7fY），UP-Sings，152 秒，1280×720。
本地文件：`/workspace/reference/av19390801-guichu-ref.mp4`
对照对象：`/workspace/demo/guichu-song/guichu-song-smooth.mp4`（48 秒，960×720）。

测量方法：BPM 用 onset 包络自相关估计；鼓组用 30–90 / 90–250 / 250–2000 / 2000–8000 Hz 四段能量折叠到 16 分网格；人声用 HDemucs 分离后做 WORLD F0 跟踪；剪辑切点用 ffmpeg scene 检测；字幕用 tesseract 中文 OCR 抽样。所有数值是可复现的近似值，不是听感评分。

| 拍号 | 4/4 | 4/4 |

| 1 小节 | 2.276 秒 | 1.997 秒 |
| 时长 | 152.0 秒（约 67 小节） | 48.0 秒（24 小节） |

**调式**：自动调性相关度最高的是 G♯ 大调（0.80），但旋律音级明显集中在 C、E♭、F、F♯、G、B♭，也就是 **C 蓝调音阶**。这解释了为什么它听起来“有味”：不是纯大调儿歌，而是大量使用 ♭3、♭5 的蓝调音。

**鼓组 16 步型**（每小节 16 个 16 分音符，0 是强拍）：


参考的 16 个格子里几乎每格都有能量（最低 0.27），我们有一半格子接近 0（0.01–0.1）。差别不是“有没有鼓”，而是**参考有连续的 16 分音符律动和 ghost note，我们的循环只在 1、3 拍上砸一下**。

**段落边界**（自动检测，秒）：6.2、9.0、27.2、33.5、42.6、45.4、60.2、103.4。
可读成：0–9 秒开场，9–27 秒第一段主歌，27–45 秒副歌（hook 重复），45–60 秒第二段主歌，60–103 秒展开，103 秒后收尾。

## 3. 台词与写歌规律

从 OCR 抽样的字幕可以确认（按镜头）：

- 26.5–31 秒连续重复“改革春风吹满地”，同一句被切成多个短镜头反复砸。
- 31–35 秒接“中国人民真争气”。
- 38–40 秒出现“耗子都给猫当伴娘”这类赵本山金句。
- 40–44 秒是“齐德隆咚锵”的拟声段。
- 45–50 秒切到“2002 年的第一场雪”，说明它不只是单曲，而是**多首梗曲/小品金句的拼贴**。

可复用的写法：

1. **一句 7 字，2 小节一句**。7 字刚好能塞进 8 个 16 分格，留一格换气。
2. **一句一镜头**。字幕、镜头、乐句三者同起同落，观众不需要追。
3. **hook 先出现，再重复 2–3 次**。重复时换素材、换景别，不换词。
4. **押韵落在句尾**：“满地/争气/世纪/咋地”，开口音收尾，方便拖长。
5. **主歌用金句堆叠，副歌只留 hook**。主歌信息密度高，副歌让观众跟唱。
6. **拟声词单独成段**（齐德隆咚锵），给剪辑留 16 分音符的花活空间。
7. **最后一句落在总结句**（“风景这边更好”），给全片收口。

## 4. 剪辑层

| 指标 | 参考 | 我们 |
|---|---|---|
| 切点数 | 60 | 6 |
| 切点/分钟 | 23.7 | 7.5 |
| 中位镜头时长 | 2.27 秒 ≈ 1 小节 | 8.0 秒 ≈ 4 小节 |
| 镜头长度分布（拍） | 0.5 拍 7 个、1 拍 11 个、2 拍 5 个、4 拍 15 个 | 以 8–16 拍为主 |

参考的切点基本落在小节线上，镜头长度以 **半小节、1 小节、2 小节、4 小节**为单位，偶尔用半拍做“抽帧式”强调。字幕固定在画面底部，白字黑边，一句一行。素材在多个机位、多个小品之间轮换，同一个人物不会连续停留超过 2 小节。

我们的项目只有 **1 个 48 秒视频 clip、1 条音乐、1 条人声**，画面里的 6 个切点来自素材本身，不是我们剪的。没有分镜，就没有卡点。

## 5. 混音层

参考人声动态只有 6.5 dB，说明做了压缩、限幅和电平自动化；我们的干声是 12.0 dB，字与字之间音量差一倍，听起来“有的字喊、有的字没声”。参考的频谱质心 P95 更高（3811 Hz），说明它保留了齿音、气口和辅音瞬态；我们是 WORLD 重合成的元音，字头被磨平。

参考还至少做了：人声前置、轻混响、和声/双击叠层、鼓组侧链压缩。这些不是调音参数，是混音工序。

---

## 6. 我们为什么做不出这种效果

按影响从大到小：

1. **没有分镜**。一个 48 秒 clip 从头的静态画面，注定没有卡点。这是第一位的原因。
2. **音高钉死**。79% 的帧在 ±15 音分内，参考只有 36%。我们把表情全削掉了。
3. **字太长**。中位 190 ms 对 90 ms，字与字之间没有 16 分音符的流动。
4. **没有辅音**。元音重合成导致字头丢失，听感发糊。
5. **没有混音**。12 dB 动态、无压缩、无叠层，音量不齐。
6. **BPM 不匹配**。120 对 105.5，律动天然更“直”、更“赶”。
7. **没有段落**。24 小节一个 loop，没有主歌/副歌的对比。

## 7. 可直接复用的模板（120 BPM 版）

现有素材是 120 BPM，先按 120 做，规律不变：

- 1 小节 = 2.0 秒；16 分音符 = 125 ms。
- 48 秒 = 24 小节。
- 结构：4 小节 intro（标题 + 第一句）→ 8 小节主歌 → 8 小节副歌 → 4 小节尾。
- **一句 2 小节，一句一镜头**；副歌改成 **1 小节一切**，最后 2 小节用半小节切。
- 字幕：底部 PNG 叠加，白字黑边，每句一条，时长等于乐句。
- 镜头来源：同一素材的不同 sourceStart，配合 1.0/1.1/1.25 三档放大，制造景别变化。
- 混音：人声 0.82、音乐 0.45；人声先做 `acompressor`（约 3:1）再入轨。

预期指标（用来验收，不靠感觉）：

- 切点 ≥ 20 个/48 秒（≥ 25 次/分钟）。
- 中位镜头 ≤ 2.5 秒。
- 80% 以上切点落在 0.5 小节网格上。
- 字幕句数与镜头数 1:1。

- [ ] 每句 7 字、2 小节，句尾押开口韵。

- [ ] 一句一镜头，切点落在 0.5 小节倍数上。
- [ ] 每个镜头换景别或换素材，避免连续 2 小节同一构图。

- [ ] 最后用切点密度、中位镜头时长、16 分落点三项指标验收。

## 10. 照搬实验：24 秒 / 120 BPM 成品

按第 7 节的模板做了一版可验收的样片，用来验证“规律能不能落地”。

- 成品：[guichu-beat.mp4](file:///workspace/demo/guichu-beat/guichu-beat.mp4)
- 工程：[project.json](file:///workspace/demo/guichu-beat/project.json)
- 伴奏：[beat.wav](file:///workspace/demo/guichu-beat/assets/beat.wav)（numpy 合成，C–Am–F–G，12 小节）
- 人声：[vocals-comp.wav](file:///workspace/demo/guichu-beat/assets/vocals-comp.wav)（6 句 hook，压缩后 8.6 dB 动态）
- 字幕：`assets/sub1.png` … `sub6.png`，一句一张，底部白字黑边

| 指标 | 参考 | 旧版 48 秒 | 本次 24 秒 |
|---|---|---|---|
| 时长 / 小节 | 152 秒 / 67 | 48 秒 / 24 | 24 秒 / 12 |
| BPM | 105.5 | 120.2 | 120（合成网格） |
| 镜头数 / 切点 | — / 60 | 1 / 6 | 18 / 17 |
| 切点每分钟 | 23.7 | 7.5 | 42.5 |
| 中位镜头 | 2.27 秒 | 8.0 秒 | 1.0 秒 |
| 切点落在 0.5 小节网格 | 大多数 | 无 | 100% |
| 人声动态 | 6.5 dB | 12.0 dB | 8.6 dB |
| 人声起音密度 | 6.94 次/秒 | 4.05 次/秒 | 4.54 次/秒 |
| 16 分格有人声起音 | 接近 100% | — | 41.7% |
| 整体响度 | — | — | −13.8 LUFS，真峰 −1.1 dBFS，LRA 0.9 |

照搬成功的部分：

1. **先定网格再排镜头**。0.5 / 1 / 2 小节三种镜头长度交替，17 个切点全部落在网格上。
2. **一句一镜头**。6 句歌词对应 6 张字幕，字幕与乐句同起同落。
3. **同一素材换景别**。1.0 / 1.05 / 1.12 / 1.20 / 1.25 五档放大并用负偏移居中，避免“一个机位看到底”。
4. **16 分律动**。鼓组 hats 铺满 16 格，第 5 小节起加 16 分琶音，补上参考片高频的连续能量。
5. **混音工序**。人声 6:1 压缩 + 限幅 + 1/16 双击叠层，动态从 27.4 dB 压到 8.6 dB，整体响度 −13.8 LUFS。

仍然没做到的：

1. **人声 flow 密度**。参考是 6.94 次/秒、几乎铺满 16 格；这次是 4.54 次/秒、41.7% 覆盖。根因是歌词本身是四分音符旋律，不是 16 分念白。下一步要把 hook 重新按 16 分音符切字（每个字 125 ms）再跑一次 autotune。
2. **多素材拼贴**。参考在多个机位、多个小品、多首梗曲之间跳；这次只有《昨天今天明天》一个来源。
3. **和声 / 混响 / 齿音**。只做了压缩和 1/16 双击，没有真正的高八度和声与混响，字头仍比参考软。
4. **画质**。源是 480×360，输出 960×720，放大后细节不如参考的 720p。

复现命令：

```bash
cd /workspace/demo/guichu-beat
python3 tools/guichu_beat.py          # 合成 120 BPM 伴奏
ffmpeg -i ../guichu-song/song-vocals-autotuned.wav \
  -af "acompressor=threshold=0.03:ratio=6:attack=3:release=60:makeup=8,alimiter=limit=0.95" \
  -ar 48000 -ac 1 assets/vocals-comp.wav
python3 tools/guichu_subs.py          # 生成底部字幕 PNG
python3 tools/make_guichu_project.py  # 生成 project.json
cd /workspace/codecut
node dist/cli.js project validate /workspace/demo/guichu-beat/project.json
node dist/cli.js render --project /workspace/demo/guichu-beat --force
```
