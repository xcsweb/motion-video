# nana 中文强节奏竖屏短片 Spec（v2）

## Why

参考视频是一支 35 秒竖屏：Gemini 界面 + AI 生成的西语「nana」动效，BGM 节奏很强。v1 已交付但用户判定不达标：**剧情不行、节奏感不足**。本版推倒重写剧情结构与节奏骨架，其余交付标准（时长、画幅、响度、卡点精度）不变。

原片音频无法获取（抖音需要登录 Cookie，网页版返回验证码），因此节奏不按原曲对齐，改为按强节奏短视频的通用规律重建。

## What Changes

- 重写剧情：从「词义对照」改为「三幕 + 反转」的完整故事。
- 重写节奏：128 BPM → **144 BPM**，21 小节正好 35.000s；切点密度阶梯式上升（1.67s → 0.83s → 0.21s → 0.08s）。
- 重写 BGM：同一 4 音动机，大调（哄睡）→ 小调（催促）→ 回大调（奶奶哼唱），全部程序化合成。
- 新增三把声音：旁白女声 / 奶奶 / AI 中性音。
- 新增「系统通知弹窗」视觉装置，弹窗卡重拍且「叮」用调内音。
- 交付物改为 v2 版本（成片 / 封面 / 联系表 / script.json / beatmap.json）。
- **不**修改现有 `scripts/`、`v4/`、`travel/`、`codecut/` 的行为。

## Impact

- Affected specs：短视频脚本、原创音乐、AI 视觉、卡点剪辑、成片交付。
- Affected code：`nana/`（`config/`、`build/`、`assets/`、`out/`）。
- Existing code：保持 v1 / v4 / travel / codecut 原样；v1 成片保留不覆盖。
- Runtime：Python 3 + Pillow / numpy / scipy、ffmpeg、Noto Sans CJK / 得意黑；可选 GenerateImage。

## 先回答：BGM 能不能复刻？

**不能 1:1 复刻原曲，但能复刻甚至超过它的“节奏强度”。**

| 方式 | 能做到什么 | 限制 |
| --- | --- | --- |
| 原创同类型 BGM（默认） | 144 BPM、四拍底鼓 + 808、两段 drop、16 分快切与闪帧，听感是“强节奏电子” | 不是原曲，音色达不到商业混音水准 |
| 使用用户提供的原音频 | 节奏 100% 一致，直接按原曲卡点 | 需要用户提供音频文件，并确认有权使用 |
| 从原视频提取音频 | 可得到原声 | 抖音需登录 Cookie，当前环境抓不到；且版权归原作者 |

## 创意稿 v2（请重点确认）

### 为什么推翻 v1

| 维度 | v1 的做法 | 后果 |
| --- | --- | --- |
| 剧情 | 只有词义对照 + 字卡，没有人物、冲突、转折 | 像科普，不像故事，看完没有情绪落点 |
| 节奏 | 128 BPM，几乎每 1.875s 才切一刀 | 只有慢推 + 花字，没有卡点爽感 |
| 记忆点 | 「一个词，两种命」重复两次 | 是解释，不是金句 |

### 一句话故事

我让 AI 用西语说一句哄睡的话，它给了我一片会发光的育婴房。
我说「那中文呢」，它给了我奶奶——收手机、拔网线、掀被子。
直到她关门前，把手机放回床头，点开了那首摇篮曲。

### 三幕结构 + 反转

| 幕 | 时间 | 事件 | 情绪 |
| --- | --- | --- | --- |
| 1 建立 | 0.000–10.000 | 打字提问 → AI 生成粉色育婴房 → nana = 摇篮曲 | 治愈、放松 |
| 2 升级 | 10.000–23.333 | 追问中文 → 奶奶登场 → 通知连招（23:47 / WiFi 断开 / 手机没收 / 被子加盖）→ 掀被、关灯、拔线、收手机 | 压迫、爆笑、越来越快 |
| 3 反转 | 23.333–35.000 | 骤停 → 奶奶把手机放回床头，播放同一首摇篮曲，轻声「nana」→ AI 收尾「两种翻译，都对。建议：听奶奶的。」 | 破防 |

**反转的作用**：把「奶奶很烦」翻成「奶奶怕你睡不够」。一句话从吐槽变成共情，评论区会二刷找细节——开头那首摇篮曲，就是结尾她放的那首。

### 节奏骨架（144 BPM / 21 小节 / 35.000s 整）

选 144 BPM 的原因：21 小节 × 1.6667s = 35.000s 整拍收尾；每拍 12.5 帧，切点误差 ≤ 半帧。
切点密度阶梯上升，是这一版「节奏感」的主要来源。

| 段 | 帧 | 时间 | 小节 | 切点 | 密度 | 内容 |
| --- | --- | --- | --- | --- | --- | --- |
| S0 输入 | 0–100 | 0.000–3.333 | 1–2 | 3 | 打字连续 | 手机屏微光，AI 输入框逐字打出「西语会说吧？就是 nana」，回车，加载圈，白闪 |
| S1 西语 | 100–300 | 3.333–10.000 | 3–6 | 8 | 0.83s/刀 | 粉色育婴房全景 / 摇篮特写 / 床铃 / 宝宝 / 月亮过曝，每半小节一刀 |
| S2 骤停 | 300–350 | 10.000–11.667 | 7 | 3 | — | 0.2s 全静音黑场，白字「那中文呢？」，心跳 ×2 |
| S3 登场 | 350–450 | 11.667–15.000 | 8–9 | 5 | 0.42s/刀 | 0.2s 白闪 + glitch → 中式客厅，奶奶转头看镜头 |
| S4 连招 | 450–600 | 15.000–20.000 | 10–12 | 20 | 0.25s/刀，末段 0.1s | 8 分快切 + 通知弹窗 ×4，最后半秒 16 分闪帧 |
| S5 高潮 | 600–700 | 20.000–23.333 | 13–14 | 8 | 0.42s/刀 | 掀被 / 关灯 / 拔线 / 收手机，每个动作落一个整拍 |
| S6 反转 | 700–800 | 23.333–26.667 | 15–16 | 4 | 留白 | 全静音 0.5s → 奶奶把手机放回床头，按下播放，轻声「nana」 |
| S7 分屏 | 800–950 | 26.667–31.667 | 17–19 | 6 | 0.83s/刀 | 左右分屏，两边呼吸同步，旋律波形一致，双画面合并 |
| S8 收尾 | 950–1050 | 31.667–35.000 | 20–21 | 3 | 打字连续 | AI 打出「两种翻译，都对。」「建议：听奶奶的。」→ end card |

合计约 60 刀 / 35s。疏密对比明确：最慢 1.67s，最快 0.08s（16 分闪帧）。

### BGM 设计：一个动机，三种性格

- **动机**：4 个音 A–C♯–E–D（大调），就是那首摇篮曲。
- S1：大调、慢速、竖琴 + 八音盒音色 → 哄睡。
- S3–S5：同一动机改成 A 小调、加倍速、加 trap 鼓组与 808 滑音 → 催促。
- S6–S7：回到大调，钢琴单音 + 八音盒 → 奶奶哼的那首。
- 通知弹窗的「叮」用调内音（E5 / A5 / C♯6），弹窗因此像乐器，不像噪音。
- 参数：144 BPM，四拍底鼓，8 分 / 16 分 hi-hat，段尾 1/2 拍 stutter，drop 前 1 拍全静音，侧链 8 dB。全部程序化合成，无采样。

### 花字 / 字幕

- 0.0–3.2 输入框：西语会说吧？就是 nana
- 3.4–9.9 nana = 摇篮曲 / 哄你睡（三个字随床铃星星落重拍）
- 10.1–11.6 那中文呢？
- 11.8–14.9 nana = 奶奶
- 15.0–20.0 系统通知 ×4：23:47 了 / WiFi 已断开 / 手机已没收 / 被子已加盖
- 20.0–23.2 掀被 / 关灯 / 拔线 / 没收（每刀一个 2 字动词）
- 23.3–26.6 无字，留白
- 26.7–31.6 同一个 nana，两种命 / 一个哄你睡 / 一个怕你睡不够
- 31.7–35.0 两种翻译，都对。/ 建议：听奶奶的。/ 中文会说吧？就是——奶奶。

### 视觉

- **西语段**：Pixar 3D 育婴房，色温 3200K，薰衣草粉 + 冷月光 + 星尘；只做缓推与 2.5D 视差，稳。
- **中文段**：中式客厅，色温 6500K 冷白 + 电视蓝光 + 一盏暖黄台灯；手持微抖、快推、甩镜、0.2s 白闪、glitch（RGB 分离 + 扫描线）。
- **通知弹窗**：iOS 风格圆角卡片，白底黑字，从顶部弹入，卡重拍。
- **字体**：西语段柔和圆体；中文段 Noto Sans CJK Black / 得意黑，红白贴纸字。

### 制作路线

1. 脚本/分镜确认（本 spec）。
2. 用 AI 生成关键帧：育婴房、摇篮、奶奶（多表情）、客厅、时钟、路由器、手机、拖鞋；统一 Pixar 3D 风格。v1 已有 11 张可复用，只需补「奶奶放手机 / 门外哼唱 / 关灯」3–4 张。
3. 用 Python（Pillow + numpy）做 2.5D 视差、粒子、文字动效、通知弹窗、glitch。
4. 合成 144 BPM 原创 BGM、三把声音的旁白/台词，输出 beat map（帧级）。
5. 用 ffmpeg 按 beat map 剪辑、叠字幕/花字、调色、混音。
6. QA：ffprobe、抽帧、响度、文字校对、卡点误差 ≤ 1 帧。

## ADDED Requirements

### Requirement: 脚本先审后做

在用户明确确认分镜、旁白和标题之前，系统 SHALL NOT 生成 BGM、视觉素材或成片。

#### Scenario: 用户确认脚本

- **WHEN** 用户确认本 spec 中的创意、分镜和旁白
- **THEN** 才开始制作

#### Scenario: 用户要求修改

- **WHEN** 用户修改创意、台词或时间点
- **THEN** 先更新本 spec 和分镜表，再次确认后才继续

### Requirement: 原创强节奏 BGM

系统 SHALL 生成 144 BPM、35.0s 的原创 BGM，包含两段 drop、808 贝斯、四拍底鼓、军鼓滚奏、riser、impact、stutter，并输出与分镜对齐的帧级 beat map。BGM SHALL 不包含任何未授权采样。

#### Scenario: BGM 与分镜对齐

- **WHEN** 读取 `beatmap.json` 与分镜表
- **THEN** 每个段落起点都落在小节线上，误差 ≤ 1 帧

#### Scenario: 用户提供原音频

- **WHEN** 用户提供原音频并确认有权使用
- **THEN** 用原音频替换原创 BGM，重新按原曲卡点，其余流程不变

### Requirement: 中文竖屏成片

系统 SHALL 输出 1080×1920、30fps、H.264/AAC、约 35.0s 的 MP4，画面包含三幕场景、中文花字、三把声音的台词和音效。

#### Scenario: 成片可播放

- **WHEN** 用 ffprobe 检查输出
- **THEN** 分辨率、帧率、时长、编码符合要求，完整解码无错误

#### Scenario: 中文文字正确

- **WHEN** 抽查每一句花字和字幕
- **THEN** 无错别字、无缺字（豆腐块）、无遮挡关键画面

### Requirement: 卡点剪辑

剪辑 SHALL 以 beat map 为准：段落切换落小节线，S1/S7 落半小节，S4 落 8 分并含 16 分闪帧，S5 每个动作落整拍。画面动作 SHALL 与鼓点或音效对齐。

#### Scenario: 卡点误差

- **WHEN** 对比成片切点与 beat map
- **THEN** 误差 ≤ 1 帧（33ms）

### Requirement: 交付与可复现

系统 SHALL 交付成片、封面、联系表、脚本 JSON 和 beat map，并保留可重跑的构建脚本。

#### Scenario: 重新渲染

- **WHEN** 运行构建脚本
- **THEN** 能从素材和配置重新生成同一支成片

## 验收标准

| 项目 | 标准 |
| --- | --- |
| 时长 | 35.0s ± 0.1s |
| 画幅/帧率 | 1080×1920，30fps |
| 编码 | H.264 + AAC，`+faststart` |
| 响度 | -14 LUFS ± 1，真峰值 ≤ -1 dBTP |
| 卡点 | 切点误差 ≤ 1 帧；S4 需实测闪帧段落 |
| 节奏 | 切点密度至少覆盖 3 档（≥1.6s / ≈0.8s / ≤0.25s） |
| 文字 | 中文无错字、无缺字 |
| 版权 | BGM 原创、视觉 AI 生成或自制、无未授权素材 |
| 标注 | 发布文案标注“AI 生成画面 / 原创音乐” |
