# Checklist

## 技术选型与范围

- [ ] 规格说明 Python 与 Node 都能承担异步任务，最终选择 Node + TypeScript 的理由与外部进程、诊断和 UI 协同一致，而非误判 Python 能力不足。
- [ ] 新工具采用 Node.js 22+、TypeScript、Execa 和 FFmpeg；旧 Python 工程未被强制迁移。
- [ ] 规格明确 Vue CLI `vue ui` 是配套图形界面、Vue CLI 已进入维护模式、Vite 是前端构建/开发工具而非通用媒体 CLI。
- [ ] 做与不做的能力均有理由，没有仅因实现复杂而排除 AI 需要的无界面功能。
- [ ] 素材库、多轨、结构化裁切、参数、预览、撤销、工程管理、异步任务和诊断均有可调用的无界面能力。
- [ ] `schema` 和 `capabilities` 足以让 AI 在不阅读全部源码的情况下构造合法工程与操作。

## 异步任务与异常生命周期

- [ ] 分析、预览和正式渲染统一生成持久化 job，支持前台等待、detach、list/show/wait/cancel/retry。
- [ ] 并行任务有明确并发上限，不会一次启动无界数量的 FFmpeg。
- [ ] 渲染固定工程修订和素材状态，项目写锁与输出路径锁能防止并发写坏文件。
- [ ] FFmpeg progress 与 stderr 分离解析，进度包含帧、时间、速度和状态。
- [ ] stdout/stderr 持续消费，日志洪峰不会造成 PIPE 阻塞或无界内存增长，日志截断有明确标记。
- [ ] Ctrl-C、SIGTERM、超时和 jobs cancel 均进入终止流程，宽限期后强杀并等待子进程退出。
- [ ] 取消、超时、启动失败、FFmpeg 非零退出、写盘失败、非法进度和 worker 崩溃有不同错误类型。
- [ ] job 心跳与进程检查能把意外退出标为 interrupted，不会永久显示 running。
- [ ] 取消/失败会清理临时文件并保留旧输出；retry 新建 job 且保留旧诊断，默认不自动重试。

## CLI 排错与诊断面板

- [ ] `doctor` 检查 Node、FFmpeg/ffprobe、滤镜、字体、权限、临时空间和任务锁，并给出具体失败项。
- [ ] `jobs show` 能定位阶段、进度、PID、起止时间、工程修订、错误和诊断文件。
- [ ] `logs` 支持按 job/stage/级别查看和 follow；TTY、CI、非 TTY 与 `--json` 输出行为明确。
- [ ] `--verbose`、`--debug` 和普通模式的信息量不同，堆栈不会污染正常 JSON 输出。
- [ ] `render --dry-run` 不启动编码，能输出执行计划、工程修订、FFmpeg 参数数组和滤镜图位置。
- [ ] `diagnose JOB_ID` 包含环境、错误、参数、滤镜图、stderr、进度、工程修订和素材元数据，默认不含原媒体或凭据。
- [ ] 稳定退出码和 JSON 错误能区分用法、校验、媒体、超时、取消和内部错误。
- [ ] Vue + Vite 面板与 CLI 展示相同 job ID、进度、状态、日志、预览和修订差异。
- [ ] 面板取消/重试调用同一核心服务，不存在浏览器专用剪辑或渲染语义。
- [ ] 面板默认仅本机监听；CI 不启动面板时全部剪辑与诊断功能仍可用。

## 素材库与分析

- [ ] 素材可登记、列表、移除和重新探测，元数据包含时长、流、编码、画幅、帧率和音频信息。
- [ ] 素材缩略图和带时间码联系表反映真实源画面，缓存会在文件状态变化后失效。
- [ ] 场景变化候选点和静音区间以机器可读时间输出，并用已知合成素材验证。
- [ ] 素材丢失或改变时，校验指出受影响素材和镜头，不静默渲染错误内容。

## 工程、结构化编辑与历史

- [ ] `project init/show/validate` 能创建、展示和校验版本化权威 `project.json`。
- [ ] 工程支持多视频轨、多音频轨，以及视频、图片、颜色和文本镜头。
- [ ] 镜头支持源入点、时间线位置、时长、速度、裁切、缩放、位置、透明度、音量和淡入淡出。
- [ ] `edit apply` 覆盖增删轨道、添加/裁切/移动/拆分/删除镜头、设置参数、添加文本和导入 SRT。
- [ ] `edit apply --dry-run` 只返回差异；真实提交返回新修订和结构化差异。
- [ ] 操作列表任一失败时全部回滚，错误包含失败操作索引和原因。
- [ ] 每次成功写操作都有不可变修订，只读/分析/渲染不产生编辑修订。
- [ ] 历史列表、修订差异、撤销和重做正确，撤销后的新编辑会截断重做分支。
- [ ] 历史操作只改变工程状态，不修改或删除原素材。

## 渲染与预览

- [ ] 多镜头裁切、重排、速度变化、硬切和 `xfade` 符合时间线，时长误差不超过一帧。
- [ ] 多视频轨按顺序合成，B-roll、图片、文本、颜色、透明度及位置/缩放/裁切参数有效。
- [ ] 多音频轨正确混合，原声缺失区间补静音，音量、淡化及变速音频同步有效。
- [ ] 文本和 SRT 字幕使用配置字体、字号、颜色和对齐，无文字转义错误。
- [ ] 正式输出为可完整解码的 H.264 / AAC MP4，48kHz 双声道，音画等长。
- [ ] `preview frame` 在合法时间输出 PNG，越界时间报错且不产生文件。
- [ ] `preview sheet` 输出带时间码的全片或指定区间联系表，采样区间和密度可配置。
- [ ] `preview proxy` 输出保留完整时间线和音频的低分辨率可播放 MP4。
- [ ] 三类预览与正式渲染共用时间线语义，代表帧中的字幕、B-roll 和跨轨布局一致。

## 文件安全、测试与回归

- [ ] 所有命令支持非交互执行、`--json` 和稳定退出码，标准输出不混入 FFmpeg 普通日志。
- [ ] 工程和媒体输出采用原子写入，默认拒绝覆盖，只有 `--force` 才覆盖。
- [ ] 渲染失败保留已有目标并清理本次临时文件，不留下伪装成成功的残缺输出。
- [ ] 示例使用仓库现有 `media/railgun_omr_v4_preview.mp4`，可从空工程重放到异步任务、诊断、预览和成片。
- [ ] 离线测试覆盖素材分析、全部结构化操作、事务回滚、历史、多轨渲染和三类预览。
- [ ] 离线测试覆盖并行、日志洪峰、取消、超时、崩溃、锁冲突、诊断包和 UI/CLI 状态一致性。
- [ ] 测试通过 ffprobe、完整解码、代表帧、音频、job 记录和工程差异验证行为，不只检查退出码。
- [ ] 未引入自研编解码器或另一套媒体内核；FFmpeg 负责媒体处理，Node 负责工程、异步和诊断。
- [ ] 既有 `scripts/`、`v4/`、旧时间线和示例行为未改变，用户文件未被删除或回滚。
