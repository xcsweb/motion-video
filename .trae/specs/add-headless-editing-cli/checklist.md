# Checklist

- [ ] 用户可以通过一个 JSON 工程引用 FFmpeg 可解码的本地视频，并复用同一素材的不同区间。
- [ ] `validate` 能在渲染前发现缺失文件、非法 JSON、错误素材 ID、越界时间、非法尺寸/帧率和非法转场。
- [ ] `render` 能按配置裁切、重排多个镜头，画幅变化不会拉伸人物或物体。
- [ ] 硬切与声明的 `xfade` 转场均有效，最终时长与“镜头时长之和减去转场重叠”一致，误差不超过一帧。
- [ ] 默认 `original` 模式保留并同步原声，无音频流的素材会自动补静音。
- [ ] `external` 模式只使用指定外部音频，音频裁切或补静音后与视频等长。
- [ ] `mute` 模式生成与视频等长的 48kHz 双声道静音 AAC 音轨。
- [ ] 输出为可完整解码的 H.264 / AAC MP4，分辨率、帧率、镜头顺序和时间点符合配置。
- [ ] `preview` 在与正式渲染相同的时间线上输出指定时间点 PNG，并拒绝越界时间。
- [ ] 所有命令无需交互确认，成功返回零状态，失败返回非零状态且错误进入标准错误。
- [ ] `validate --json` 和 `render --json` 提供机器可解析摘要，不混入 FFmpeg 普通日志。
- [ ] 默认不会覆盖已有输出；只有 `--force` 才覆盖，失败时已有目标不变且不遗留本次临时文件。
- [ ] 示例工程使用仓库现有 `media/railgun_omr_v4_preview.mp4`，可在本地完成校验、渲染和抽帧。
- [ ] 自动化测试使用临时合成素材且无需联网，覆盖重排、转场、三种音频、预览、非法输入和覆盖保护。
- [ ] 未新增 GUI、庞大媒体框架或自研编解码器，Python 实现只依赖标准库和系统 FFmpeg / ffprobe。
- [ ] 既有 `scripts/`、`v4/`、时间线和旧示例行为未被改变，用户已有文件未被删除或回滚。
